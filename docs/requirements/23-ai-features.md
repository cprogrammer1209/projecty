# 23 — AI Features
Code: `AI` · Phase: 6 · Service: Work (AI module) · Status: **Outline**

## 1. Purpose
Use LLMs to save people time (summaries, drafting) and surface problems earlier (insights), without leaking data across permission boundaries.

## 2. Scope by tier
| Tier | Features |
|---|---|
| MVP | Summarize a task or issue's comment thread. Generate a task description and a subtask breakdown from a title. Admin toggle to enable or disable AI per portal. |
| V1 | Natural-language querying ("show overdue critical issues in Website Revamp") that turns into a view filter. Project status summary (weekly narrative). Insights: detect bottlenecks (items stuck in a status), at-risk phases, overloaded users. MCP server so external AI assistants can query and act on data with the user's permissions. Bring-your-own-model: configure the provider and API key per portal. |
| LATER | AI-assisted custom module builder. Generate a whole project from a requirements document. Semantic search. Translation. |

## 3. Key business rules
- **AI-BR-01** The AI only sees data the requesting user can see. Context is assembled with the same permission filters as views and search.
- **AI-BR-02** AI never changes data without explicit user confirmation. Suggestions are previewed and then applied by the user.
- **AI-BR-03** Portals can disable AI entirely. When it's disabled, no portal data is sent to any model provider.
- **AI-BR-04** AI-generated content is labeled as such where it is saved (e.g., "Summary generated by AI").
- **AI-BR-05** Usage is metered per portal and can be limited by entitlement.

## 4. Business events
`AiSummaryGenerated`, `AiSuggestionApplied`, `AiQueryExecuted` (for metering).

## 5. Dependencies
Tasks (06), Issues (11), Views (08), Search (12), Reports (20), Public API (22) for MCP.
